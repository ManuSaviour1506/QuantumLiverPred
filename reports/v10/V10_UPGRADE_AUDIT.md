# V10 upgrade — status of the audit findings (V10_case_review_and_audit.pdf, 13 Nov 2026)

Nothing below hides a problem to make the dashboard look better. "Fixed" means fixed in code and covered by a test;
"mitigated" means the platform now detects and reports it, but the underlying data or model limitation remains.

| # | Finding | Status | What changed | Evidence |
|---|---|---|---|---|
| 1 | Missing timm ImageNet backbone weights: models listed "available", every prediction crashed | **Fixed** | `artifacts/manifests/weights_manifest.json` (file, size, SHA-256, official URL); `src/v10/engine/weights.py` verifies at engine load; models depending on a missing backbone become `missing_dependency` with the reason; `scripts/fetch_weights.py` downloads + verifies; `setup.sh` and both Dockerfiles call it; `ood_detector` / `liver_gate` status now require the weights | `/api/v1/models/availability`, Overview "System status"; `tests/test_compare.py::test_availability_registry` |
| 2 | Liver gate accepted heart tissue on ct_lits_4353 → 5 models reported a tumour | **Fixed (on the sample); needs full-data validation** | Two-stage liver check: patch gate AND V9 U-Net liver area ≥ `LTI_LIVER_MIN_UNET_PX` (4096 px). Applied to comparison runs, V10 single predictions and V9 single predictions. Gate threshold and tumour models unchanged | 4353: U-Net 3,200 px → withheld; tumour slices 6,976–37,248 px → analysed. `reports/v10/LIVER_GATE_VALIDATION.md`; `test_liver_free_heart_slice_is_not_analysed`. The 4,096 px default was chosen with this audit case in view, so it must be re-checked on the full dataset (`scripts/v10_validate_liver_gate.py --split validation`, then once on test) |
| 3 | Decision tree returned p = 0.855 on every slice → always Uncertain | **Fixed (marked non-deployable)** | Generic check for models whose calibrated probability is bounded (trees, forests, k-NN, boosting, MLP): if the maximum attainable probability is below threshold + band, the model can never call a tumour → `non_deployable`. Only `v10_decision_tree_radiomics` fails (bound 0.855 = its threshold). Its threshold was **not** changed: no validation data is available here to re-select it | registry reason text; `test_upload_validation_and_compatibility` |
| 4 | Deep models return p ≈ 1.000 on tumour slices | **Investigated; mitigated** | `scripts/v10_calibration_report.py` → `reports/v10/CALIBRATION_AND_SATURATION.md`. Cause: Platt scaling fitted on near-perfectly separable V9 validation groups gives slopes of 9–31 on the standardised score; test ECE is higher than validation ECE for every CNN (1.3–12×) and specificity often drops (e.g. cnn5s_v9 val ECE 0.007 → test 0.084, specificity 0.80). The best-calibrated CNN on test is cnn25d_v9_a3_res_se (ECE 0.020, spec. 0.996). Every result now carries `saturated`, its calibration source, and a decision margin instead of a "confidence" that looks like certainty. No model was re-calibrated (that requires the full dataset and would change validated models) | calibration report; UI "sat." badge |
| 5 | Context-dependent models could not run on the sample | **Fixed in the workflow; data limitation remains** | Upload accepts previous/next and two-slices-each-side; dataset samples attach their real neighbours from the same scan automatically; 5-slice stacks are built for cnn3d_v9 / cnn5s_v9; models without enough context are listed as `needs_context` with the exact requirement. The 8-slice sample still has no 5-slice run, so cnn3d / cnn5s can only run on the full dataset or user uploads with 4 neighbours | `test_run_selected_and_failure_isolation`, compatibility table |
| 6 | Runtime dependence on results/v9/cnn_selection.json | **Fixed** | Deployable copy at `artifacts/manifests/v9_cnn_selection.json`; the registry reads it first (results/ only as fallback). This is the single 3-line change to the vendored V9 code (`src/inference/registry.py`) | engine loads 6 CNN-embedding models without results/ |
| 7 | Registry did not reflect runtime availability | **Fixed** | Availability categories: available, requires_context, missing_dependency, missing_weights, legacy, not_trained, failed_integrity, non_deployable; dependency list per model; last successful inference; unavailable models are never silently excluded from a run | Model Registry page; `test_availability_registry` |
| 8 | Regression tests for tumour-free, liver-free and OOD inputs | **Added** | heart slice (4353), no-liver slice (4354), synthetic OOD phantom, failure isolation, cancellation, concurrent-run isolation, SSE event order, privacy | `backend/tests/test_compare.py` (15 tests), `frontend/e2e/compare_ui_test.py`, `frontend/tests/compare.test.ts` |

Still not possible in this folder: accuracy on the full test split (dataset absent in the lean release), re-selection
of the decision-tree threshold, re-calibration of the V9 CNNs, and running cnn3d_v9 / cnn5s_v9 on the bundled samples.
